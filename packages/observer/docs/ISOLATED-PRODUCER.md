# Isolated producer acceptance criteria

**Status:** design target; the current prototype has not passed these tests.

## Problem

The prototype signs brokered file writes and a witnessed hash-chain history, but the sample agent is not isolated from the observer. A second key and a prior commitment make a record checkable; they cannot establish that the observer stood outside the agent's reach. The current record therefore says `witnessScope: PEER` and `unmediatedEffects: not-established`.

## Acceptance criteria

1. **Threat and authority boundary.** Document agent privileges, host operator privileges, observer privileges, and external witness privileges separately. Before launch, pin the exact agent image/binary digest, work-tree root, authorized path scope, broker operation set, policy digest, interval ID, observer build/configuration digest, and expiry in one canonical authority document. A host-side observer chooses the nonce and signs the prior commitment to `authorityDigest`, `beforeRoot`, `intervalId`, and that nonce before any agent execution. A consumer pins the observer key out of band.
2. **Isolation as an exercised mechanism.** Launch an unmodified agent under a platform boundary where it cannot address the observer process, signing key, history, witness state, or watched tree except through the mediated interface. Record the exact namespace/mount/network/UID policy and measured build. CI must show a direct filesystem write, key read, process signal, and alternate channel attempt refused. If an isolation setup step fails, emit an incomplete record and no `below-observed` claim. An ordinary subprocess and two keys on one host do not satisfy this item.
3. **One bounded effect channel first.** Mediate file replacement under a literal path scope. Journal intent, accepted/denied outcome, request ID, content digest, and before/after roots durably before returning success. An identical lost-response retry must return the original effect; a changed retry must be refused. No claim about reads, transient writes, network traffic, file modes, or arbitrary tool effects is permitted by this channel. Report exact attempted, accepted, denied, replayed, dropped, and unresolved counts.
4. **Coverage that can fail.** Bind the population and interval in the record. Detect queue overflow, broker crash, failed fsync, partial snapshot, unobserved writable mount, and missing liveness/heartbeat as named gaps. A gap prevents an absence claim even if the final state equals the initial state. The observer must not infer complete coverage from an empty event list or an agent-supplied trace. Use an atomic snapshot or a mediated write path whose isolation is independently exercised; a sequential tree walk alone is inadequate.
5. **Witness and offline history.** Append events with sequence and domain-separated hashes. Preserve the before-interval commitment and the final result under a separately operated witness that retains its highest accepted head and rejects forks. Export signed checkpoints with inclusion and consistency evidence. An offline consumer holding a pinned witness key and head must detect deletion, reorder, replay, divergent heads, and a missing interval. State explicitly that a single local operator controlling both keys can still forge or withhold the entire history.
6. **Standard statement and independent reader.** Emit the existing Observed Effect draft as a DSSE-wrapped in-toto statement, subject digest equal to `afterRoot`, with signed prior commitment, normalized scope, declared gaps, and explicit `doesNotAssert`. Reuse the pinned vocabulary, `jcs-admit` and `dsse` byte rules. Run the published observed-effect corpus against a named external verifier with a report showing every vector was executed; the producer must separately pass integration cases against actual observed effects. No self-test or reference rail alone constitutes independent conformance.
7. **Reproducible adversarial demonstration.** Publish exact source revisions, launch policy, pinned keys, authority, signed record, history proofs, fixture bytes, commands, and raw results for: normal write, self-reported no-write contradicted by an observed write, direct-write bypass, traversal/symlink, lost response and retry, broker death, missing event, checkpoint fork, and observer key exposure attempt. Include any null or failed run. A second operator must reproduce at least the offline verification and one live effect run before the README calls the producer independently observed.

## Release decision

The first release may say: *“A host-side observer recorded durable changes on this declared file-write channel from a boundary the test agent could not address, under this launch configuration and these pinned keys.”* It may not say that all agent actions, all filesystem effects, or the host operator's honesty were proven. The observer's key custody and the witness operator must be named so a consumer can choose whether that trust boundary is adequate.
